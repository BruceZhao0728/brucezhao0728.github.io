# 双语内容维护设计

## 现状

迁移前，GitHub Pages 从仓库根目录直接发布 12 个静态页面。`en/` 和 `zh/` 各有首页、研究、博客列表、文章详情、兴趣和荣誉。两个版本共用 CSS 和浏览器脚本，页面文案、图片说明、无障碍标签和搜索引擎元数据分别写在两份 HTML 里。根目录的兼容页面按访客保存的偏好或浏览器语言跳转。

`data/blogs.json` 已经按文章记录中英文标题和摘要，以及共享的日期、分类、标签和 Markdown 路径。文章详情读取该目录，博客列表却把相同的信息手工写进了两份 HTML。音乐播放器读取 `data/music.json`，部分初始歌曲信息也出现在兴趣页 HTML 中。

## 需求与边界

- 在仓库中按页面查找文案，同一段的 `zh` 和 `en` 相邻。导航、通用标签、页面元数据、照片说明和交互提示也遵循这一结构。
- 两个版本可以自由措辞，允许某个段落只在一个版本出现。保留现有排版、内容和链接。文件和资源仍使用原来的公开路径。
- 修改博客标题或摘要只编辑文章目录。文章正文维持原文 Markdown，音乐目录和简历文件继续按现有方式维护。
- GitHub Actions 在推送到 `main` 后构建并发布静态 HTML。仓库跟踪源文件，生成的中英文页面按原路径发布。

## 内容、模板与生成规则

`data/pages/` 每页一份 JSON，`shared.json` 管导航和通用文案。每个可翻译字段用 `{ "zh": "…", "en": "…" }` 表示，字段名按章节和内容命名。模板中的 `{{text:键}}` 插入转义后的文本或属性值。`{{html:键}}` 用于需要保留内联标签的少数段落，接受仓库维护者提供的 HTML。`{{optional:键}}…{{end}}` 根据当前语言是否存在对应字段，决定整段标记是否输出。必填字段缺失、类型错误或引用错键时，构建报出页面和字段。

例如，首页开场介绍在 `data/pages/home.json` 的 `hero.description`，对应 `templates/home.html` 中的 `{{text:hero.description}}`。修改现有文案只需编辑 JSON。新增段落时，在 JSON 中添加一条记录，并在模板的目标位置引用它。单语段落在记录中只填要展示的语言，并把整段包在 `{{optional:键}}` 和 `{{end}}` 之间。修改博客计数或封面替代文本时，保留 `{count}` 或 `{title}`，浏览器会把它替换成实际值。

`templates/` 放共享外框及每页布局，包括固定类名、元素 ID、资源路径。生成器负责语言版 URL、canonical、hreflang 及 `<html lang>`。浏览器脚本所用的少量翻译随页面生成，以保持首次加载和运行时文案一致，无需额外请求翻译文件。

博客卡片、搜索文本和标签列表从 `data/blogs.json` 生成。按日期降序排列，保留分类、标签和文章链接。文章详情继续从同一目录读取文章信息，切换语言时保留 `id`。音乐的初始歌曲标题、作者和封面可与运行时共用目录里的首支歌曲，原有静态歌词片段和提示保留。

`npm run build` 生成并覆盖 `en/` 和 `zh/` 的对应 HTML，`start.sh` 本地预览时也会先构建。`npm run check` 比对磁盘页面与内存中的生成结果，再检查路由、图片和文章链接。GitHub Actions 构建并通过检查后，把页面、根目录跳转和公共资源打包到 `_site/`，再部署到 GitHub Pages。

## 迁移计划

1. 以当前 12 页为迁移基准。提取相邻双语文案和可复用布局，并保留研究页单语论文原题、图片替代文字及原有富文本标记。
2. 接入静态构建和博客卡片生成。把搜索计数、文章详情提示、播放器提示接到生成的本地化文案。
3. 生成静态页面，更新编辑、预览、发布说明。
4. 比对所有页面的正文、资源路径、导航和元数据。验证新增或修改文章时两份列表正确更新，并验证检查能识别未重新生成的页面。

## 验收标准

- 修改任意已迁移的双语文案时，通过同一条记录找到两种语言。运行构建后打开对应页面可以看到修改。
- 12 个页面和已有跳转路径继续可用。切换文章详情语言后仍打开同一篇文章，博客过滤和排序继续工作。
- 两份列表的标题、摘要和详情页来源一致。图库、音乐和简历链接仍可用。
- `npm run build` 可重复执行，`npm run check` 在静态 HTML 过期时失败。现有站点检查通过。
